## 1. ما تم بناؤه

تطبيق جوال (iOS وAndroid) لصناعة القصص التفاعلية بالذكاء الاصطناعي، بتصميم سينمائي فانتازي داكن مع لمسات ذهبية، يدعم العربية والإنجليزية بالكامل.

**الأنماط الثلاثة:**

| النمط | الوصف |
|---|---|
| **مغامرة تفاعلية** (الميزة الرئيسية) | ٥–٦ مشاهد، كل مشهد غير نهائي فيه ٣ خيارات بالضبط تغيّر مسار القصة، ونهاية حقيقية بدون خيارات |
| **قصة قصيرة** | قصة أصلية ٤٠٠–٦٠٠ كلمة بمقدمة وصراع وتحوّل ونهاية |
| **قصة قبل النوم** | قصة هادئة مناسبة لعمر الطفل (٣–٥، ٦–٨، ٩–١٢) بنهاية مريحة |

**الشاشات (١٣ مسارًا):** الشاشة الافتتاحية، الرئيسية، اختيار النمط، صنع البطل (٤ خطوات)، اختيار العالم (٨ عوالم + عالم مخصص)، إعداد القصة، شاشة التوليد، قراءة القصة، المغامرة التفاعلية، النهاية، المكتبة، الإعدادات، وشاشة طوارئ للأخطاء.

## 6. كيف يعمل توليد القصص

1. المستخدم يختار البطل والعالم والنوع والأجواء والفكرة واللغة.
2. لكل نمط **تعليمات نظام منفصلة** (قصيرة / مغامرة / قبل النوم) تطلب ردًا بصيغة JSON.
3. الرد **لا يُعرض قبل التحقق منه**: استخراج JSON حتى لو أحاطه النموذج بنص أو "تفكير" مسرّب، ثم فحص الطول والحقول.
4. **سياسة محاولات محدودة** لتوفير الطلبات المجانية:
   - رد غير صالح ← محاولة واحدة إضافية بنفس النموذج.
   - خطأ خاص بالنموذج (404، 429، 5xx، رد فارغ) ← الانتقال للنموذج البديل.
   - مفتاح خاطئ، انقطاع الشبكة، الحد اليومي، أو إلغاء المستخدم ← توقف فوري.
5. كل الأخطاء (400، 401، 402، 404، 429، الحد اليومي، الشبكة، المهلة، الرد الفارغ، JSON غير صالح، خيارات ناقصة) تظهر **برسالة واضحة بالعربي أو الإنجليزي** مع زر "حاول مجددًا"، والتطبيق لا ينهار.

## 7. كيف تعمل الخيارات التفاعلية

- محرك المغامرة يحتفظ **بحالة مختصرة** بدل إرسال القصة كاملة كل مرة: هوية البطل، العالم، المكان الحالي، الهدف، الرفاق، الاكتشافات، ملخص كل مشهد، وكل خيار اتخذه اللاعب.
- كل طلب جديد يحمل **الخيار الأخير صراحة** + ملخص المشاهد السابقة + ذاكرة القصة.
- قواعد صارمة:
  - المشهد غير النهائي يجب أن يحتوي **٣ خيارات مختلفة بالضبط**، وإلا يُرفض ويُعاد طلبه.
  - النهاية المبكرة (قبل المشهد الخامس) مرفوضة.
  - المشهد السادس **نهاية إجبارية** — لا مغامرات بلا نهاية.
- **الخيار يُحفظ قبل طلب المشهد التالي**، فلو فشل الطلب لا تضيع القصة، ويكمل اللاعب من نفس النقطة.

---

## 8. كيف يعمل الحفظ المحلي

- المغامرات **تُحفظ تلقائيًا** بعد كل مشهد وكل خيار.
- القصص القصيرة وقصص النوم تُحفظ بزر "احفظ القصة".
- كل قصة محفوظة تحتوي: العنوان، النمط، اللغة، التاريخ، النص، التقدم، معلومات البطل، والخيارات السابقة.
- المكتبة: فتح، إكمال مغامرة، حذف مع تأكيد، وتبويبات تصفية.
- البيانات التالفة لا تكسر المكتبة — تُتجاهل القصة التالفة فقط.
- لا يوجد خادم ولا حسابات ولا قاعدة بيانات سحابية.

## 10. القيود المتبقية (بصراحة)

1. **المفتاح داخل التطبيق:** هذا نموذج أولي تعليمي. المفتاح مضمّن في حزمة التطبيق ويمكن استخراجه. **لا تنشر هذه النسخة للعامة** — يجب إضافة خادم وسيط قبل أي إطلاق.
2. **الحد اليومي المجاني:** حساب OpenRouter بدون رصيد محدود بعدد قليل من الطلبات المجانية يوميًا. وصلنا للحد أثناء الاختبار. إضافة رصيد ترفعه إلى 1000 طلب/يوم.
3. **جودة النماذج المجانية متغيرة:** قد تسرّب "تفكيرها" أو ترجع ردًا فارغًا أحيانًا — التطبيق يعالج ذلك، لكن قد تحتاج محاولة إضافية.
4. **صور الأطفال:** قصص قبل النوم تستخدم رسمًا متجهيًا (قمر ونجوم) وليس لوحة مرسومة.
5. **الاتجاه في Expo Go:** على جوال لغة نظامه عربية قد يتطلب أول تشغيل إعادة فتح؛ التطبيق يعالج الاتجاه داخليًا.
6. **غير مضاف في الإصدار الأول (حسب الطلب):** الصوت، توليد الصور والفيديو، الدفع، الحسابات، المزامنة السحابية، الإشعارات — البنية جاهزة لإضافتها في الإصدار الثاني.

## 12. كيف تجرّب التطبيق

**التشغيل:**
```bash
npm install
npm start
```
(تأكد من وجود `.env.local` بمفتاحك — انظر `.env.example`)

**على Android:** ثبّت **Expo Go** من Google Play ← امسح رمز QR الظاهر في الطرفية من داخل Expo Go.

**على iPhone:** ثبّت **Expo Go** من App Store ← امسح رمز QR بكاميرا الجوال.

**مهم:** الجوال والكمبيوتر على نفس شبكة Wi-Fi. التطبيق يُشغَّل بوضع الشبكة المحلية (LAN) عمدًا، لأن الرابط العام (tunnel) يسمح لأي شخص يملك الرابط باستخراج المفتاح.

**أوامر مفيدة:**
```bash
npm test               # 98 اختبارًا آليًا
npm run test:live      # اختبار حقيقي مع OpenRouter (~10 طلبات)
npm run check:secrets  # التأكد من عدم رفع أي مفتاح
```
